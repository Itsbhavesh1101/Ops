# Phase 1 Task 1G.1 / 1G.1A — Canonical Versioned Event Envelope Contract

## 1. Purpose & Scope

Task 1G.1 (hardened in Task 1G.1A) establishes the canonical, provider-neutral, versioned event envelope contract for the E-7 Operations Engine.
This contract defines the unified structural, semantic, and immutability model for domain and system events across service boundaries, designed for:
1. Future persistence in the transactional Outbox (Task 1G.2).
2. Broker-neutral message transport over RabbitMQ (Task 1G.3).
3. Consumer deduplication and idempotent processing via Inbox (Task 1G.4).
4. Long-term contract evolution and safe versioning across heterogeneous services.

**Critical Scope Boundary**:
Task 1G.1 establishes **contracts and in-memory validation only**.
- ZERO database tables or migrations are added (no `outbox_events`, `inbox_messages`).
- ZERO RabbitMQ/AMQP dependencies or connection clients are introduced.
- ZERO publishers, consumers, retry dispatchers, or background workers are created.

## 2. Caller Input vs. Canonical Event Envelope

To maintain strict ownership of canonical metadata, the architecture separates caller event input from the canonical envelope through two distinct immutable Pydantic models:

```
+------------------------------------+
|            EventCreate             |  (Caller input contract)
| - event_type: str                  |
| - event_version: int = 1           |
| - tenant_id: str | None            |
| - correlation_id: str | None       |
| - causation_id: UUID | None        |
| - subject_type: str | None         |
| - subject_id: str | None           |
| - payload: Mapping[str, Any]       |  <-- Recursively frozen MappingProxyType
+------------------------------------+
                  |
                  | create_event_envelope(event, clock=...)
                  v
+------------------------------------+
|           EventEnvelope            |  (Canonical event contract)
| - event_id: UUID                   |  <-- Generated by E-7 factory (uuid4)
| - occurred_at: datetime            |  <-- Generated by E-7 factory (UTC)
| - event_type: str                  |
| - event_version: int               |
| - tenant_id: str | None            |
| - correlation_id: str | None       |
| - causation_id: UUID | None        |
| - subject_type: str | None         |
| - subject_id: str | None           |
| - payload: Mapping[str, Any]       |  <-- Recursively frozen MappingProxyType
+------------------------------------+
```

### 2.1 Immutability Distinctions (Task 1G.1A Hardening)
The architecture rigorously separates four distinct layers of immutability and data isolation:

1. **Pydantic Model Immutability (`frozen = True`)**:
   Prevents reassignment of top-level model attributes (e.g. `event.event_type = "other"` or `event.payload = {}`).
2. **Recursive Payload Immutability**:
   `frozen = True` and `deepcopy` alone do not prevent mutating nested dictionary or list items. Task 1G.1A converts validated payload structures into recursively immutable standard-library representations:
   - Dictionaries $\rightarrow$ `types.MappingProxyType` (read-only mapping).
   - Lists $\rightarrow$ `tuple` (read-only sequence).
   - Scalars (null, bool, int, finite float, str) $\rightarrow$ unchanged.
   Direct mutations such as `event.payload["k"] = v`, `envelope.payload["nested"]["k"] = v`, or `envelope.payload["items"].append(...)` raise `TypeError` or `AttributeError`.
3. **Source-Reference Isolation**:
   `freeze_payload` builds fresh dictionaries for each `MappingProxyType` and fresh tuples for each sequence. Mutating the caller's source dictionary or nested lists after passing them to `EventCreate` or `create_event_envelope` cannot affect the canonical event state.
4. **Serialization / Thaw Boundary**:
   The internal `MappingProxyType` and `tuple` nodes are never exposed as a burden to downstream serialization or consumers. `@field_serializer("payload", mode="plain")` and [`thaw_payload`](file:///f:/operations-engine/app/events/validation.py) recursively thaw the payload back to standard JSON-native `dict` and `list` structures during `model_dump(mode="json")` and `serialize_event_envelope`.

## 3. Canonical Metadata Ownership

### 3.1 Event ID (`event_id`) Ownership
- `event_id` is an authoritative, immutable canonical UUID (`UUID`).
- `EventCreate` explicitly omits `event_id`. Any caller attempting to supply `event_id` in input is rejected by `extra="forbid"`.
- `create_event_envelope(...)` unconditionally assigns a newly generated `uuid4()`. Two identical `EventCreate` instances produce distinct canonical `event_id` values.

### 3.2 Timestamp (`occurred_at`) Ownership
- `occurred_at` represents the authoritative creation moment of the canonical event envelope.
- `EventCreate` explicitly omits `occurred_at`. Callers cannot supply or backdate canonical event timestamps.
- `create_event_envelope(...)` generates a timezone-aware UTC datetime (`datetime.now(UTC)`).
- If naive datetimes are encountered, they are strictly rejected.
- An optional injectable `clock: Callable[[], datetime]` parameter is supported for deterministic unit and replay testing.

## 4. Event Classification & Versioning

### 4.1 Namespaced Event Type (`event_type`)
- Must match the bounded namespaced regex: `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`
- Minimum length 3, maximum length 128 characters.
- Requires at least two dot-separated segments in lowercase alphanumeric and underscore characters.
- Rejects uppercase characters, leading/trailing whitespace, and single-segment words.

### 4.2 Extensibility & Known Event Evidence
Task 1G.1 adopts an open, bounded namespaced pattern rather than a closed enum.
Source-verified Phase-0 event types are validated as conforming examples:
- `task.blocked`
- `workflow.task.created`
- `workflow.sla.warning`
- `schedule.published`

Future namespaced event types conforming to the pattern are accepted without requiring schema changes.

### 4.3 Event Version (`event_version`) Semantics
- Positive integer (`>= 1`), defaults to `1` in `EventCreate`.
- Represents the payload structure and semantics contract for that specific `event_type`.
- Distinct from database schema migrations, API routes (`/api/v1`), or audit schema versions.
- String version tags (e.g. `"v1"`, `"1.0"`) are prohibited.

## 5. Tenancy, Correlation, Causation & Subject Semantics

### 5.1 Canonical Tenant Reference (`tenant_id`)
- Opaque canonical string identifier (`max_length=255`).
- Nullable only for system/platform events that lack tenant context.
- Never derived or parsed from JWT claims, email domains, Google hosted domains (`hd`), or payload content inside the event contract.

### 5.2 Correlation ID (`correlation_id`)
- Optional bounded string (`max_length=128`).
- Carries request or distributed business operation trace context across components.
- Non-unique: multiple events participating in the same workflow or operation share the same `correlation_id`.
- Never substituted for `event_id`.

### 5.3 Causation ID (`causation_id`)
- Optional canonical `UUID`.
- Identifies the direct causal parent event (`A -> B -> C` where `B.causation_id = A.event_id`).
- Distinct from `correlation_id` (which remains constant across a full cascade).
- Does not require a local database foreign key or assert that the causal event is locally persisted.

### 5.4 Subject Pair-Consistency (`subject_type`, `subject_id`)
- `subject_type`: Bounded canonical identifier matching `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*$` (`max_length=128`).
- `subject_id`: Opaque string identifier (`min_length=1, max_length=255`).
- **Enforced Pairing Rule**: Both fields must be `None` or both must be present. A `subject_type` without `subject_id`, or a `subject_id` without `subject_type`, raises a validation error.

## 6. Payload Contract, Technical Limits & Security

### 6.1 JSON Primitive Strictness
Event payload root must be a dictionary/mapping. Supported leaf types:
- `None` (null)
- `bool`
- `int`
- `float` (finite numbers only)
- `str`
- Nested `list` and `dict` (keys must be strings)

**Strict Float Validation**: Non-finite floating point numbers (`NaN`, `+Infinity`, `-Infinity`) are strictly rejected recursively.
Unsupported Python types (sets, tuples, exceptions, custom classes, ORM models) are strictly rejected.

### 6.2 Technical Defensive Bounds
Payload technical bounds protect memory and serialization throughput across brokers and storage:
- `MAX_EVENT_PAYLOAD_BYTES = 262144` (256 KiB serialized UTF-8 JSON size).
- `MAX_EVENT_PAYLOAD_DEPTH = 12` (maximum recursive object/list nesting depth).
- `MAX_EVENT_STRING_LENGTH = 16384` (16 KiB maximum length for individual string values).

### 6.3 Sensitive Key Denylist
Events traverse networks and outbox tables. Obvious secret-bearing credentials are recursively prohibited in payload keys.
The key denylist normalizes case and separator punctuation (`_`, `-`, `.`):
- `password`, `passwd`
- `secret`, `clientsecret`
- `apikey`
- `accesstoken`, `refreshtoken`, `idtoken`
- `authorization`
- `cookie`
- `privatekey`

Any matching key at root or any nested structure raises a `ValueError`.

### 6.4 Defensive Payload Isolation & Conversion Pipeline
The validation and immutability pipeline in [`validate_event_payload`](file:///f:/operations-engine/app/events/validation.py):
1. **Root Type Invariant**: Asserts root is a `Mapping`.
2. **Recursive Invariants**: Recursively enforces JSON types, finite floats, and key denylist.
3. **Size Limit Invariant**: Thaws and tests serialized UTF-8 byte size ($\le 256$ KiB).
4. **Recursive Freezing**: Calls `freeze_payload` to convert mappings to `MappingProxyType` and sequences to `tuple`.

Because the internal mapping and sequence nodes are immutable, callers cannot perform post-validation credential injection (`access_token`, `password`) or float corruption (`NaN`, `Infinity`).

## 7. Deterministic Serialization Boundary

The module provides [`serialize_event_envelope`](file:///f:/operations-engine/app/events/serialization.py) as a provider-neutral serialization boundary:
- Outputs deterministic, compact UTF-8 JSON string.
- `sort_keys=True`: Guarantees reproducible byte output.
- `separators=(",", ":")`: Minimizes serialization overhead.
- `allow_nan=False`: Ensures strict RFC 8259 compliance.
- Serializes `UUID` to standard hex-hyphenated string and `datetime` to UTC ISO-8601 format.
- Envelope objects are never mutated by serialization.

Standard `envelope.model_dump(mode="json")` produces JSON-native dict and list structures via the plain field serializer.

## 8. Provider-Neutral Architecture & Absence of RabbitMQ / DB

1. **No Transport Fields in Envelope**:
   `EventEnvelope` contains zero AMQP/RabbitMQ transport fields (no `exchange`, `routing_key`, `queue`, `delivery_tag`, `consumer_tag`, `redelivered`, or broker URLs).
2. **No Persistence in Task 1G.1**:
   Zero database tables or Alembic migrations are created. The database metadata remains strictly `audit_events` (from Task 1F), and migration revisions remain `0001` and `0002`.
3. **No RabbitMQ Dependencies**:
   `pyproject.toml` remains completely unmodified. Zero AMQP libraries (`pika`, `aio-pika`) are imported or installed.
